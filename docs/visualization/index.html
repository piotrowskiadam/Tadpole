Understand the site, one question at a time.

Five complementary views for a native SEO crawler, with a shared selection and a loading model designed for larger crawls. Palette, typography and density follow Tadpole’s GTK / Libadwaita conventions.

Design proposals, pending review. The diagrams use synthetic examples and static annotations; they are not running application screens. Display limits and latency budgets are provisional. System light/dark appearance is supported without downloaded fonts, scripts or assets.

01 · Directory area

Find large sections, then switch the weight to bytes or pages with issues.

Read it as
URL containment within an origin; area is a chosen additive measure.
On selection
Open the folder, inspect its URL table, or apply the same selection to another view.
Loading strategy
Build the directory index once per snapshot. Cache rectangles by metric, focus and viewport; collapse the small tail into a named Other group.

02 · Link-depth tree

Find pages that take too many links to reach from the start URL.

Read it as
One shortest-path parent per reachable URL. It does not display every internal link.
On selection
Reveal the complete path, expand children, and open the actual incoming-link evidence.
Loading strategy
Compute BFS once per start URL. Begin with three visible levels; retain collapsed counts and focus one branch. Keep unreachable and unknown-start states explicit.

03 · URL link neighborhood

Inspect the links that can explain one page’s position or a broken destination.

Read it as
Unique URL pairs, with arrows indicating direction. Repeated link occurrences are a separate metric.
On selection
Inspect source/target rows, focus a neighbor or expand one group. Preserve the selected URL across modes.
Loading strategy
Start with one hop. Proposed initial cap: 250 nodes / 500 edges, with shown/total counts and explicit expansion. No global force layout during opening.

04 · Section link matrix

Compare connections between sections without laying out every URL.

Read it as
A complete section-to-section cross-tab; within-section links occupy the diagonal.
On selection
Open the source/target URL pairs for a cell, with section filters applied to the main table.
Loading strategy
Aggregate CSR edges once. Proposed display cap: 40 × 40 groups; combine the remaining groups into Other and preserve their totals.

05 · Depth and internal rank

Triage pages that may deserve a shorter route from the start URL.

Read it as
One URL per point in the small-site view; labelled density bins for large sites.
On selection
Select a region to open its URLs, then inspect the chosen page in the neighborhood view.
Loading strategy
Compute rank in a cancellable worker only when needed. For large crawls, prepare a bounded density grid plus selected/outlier points; use exact counts, not an unlabelled sample.

06 · Loading and interaction

Make opening, changing views and moving the pointer inexpensive.

Read it as
A bounded latest-request queue with explicit accepted and discarded outcomes.
On selection
Show current preparation status, allow cancellation and retry, and keep the selected URL and last usable frame.
Loading strategy
Window chrome first, aggregates next, detailed layouts on demand. Provisional targets and the reproducible CPU baseline are documented in the accompanying design report.
